GenData Pipeline — Data Generation Plan

Modular generator: AR / ARIMA signals × predefined / ML-model events. CSV output. Isolated in GenData/pipeline/.

Goal

Upgrade the generator to produce datasets for any combination of a signal generator and an event generator. Scope is data generation only — recognition models (SVM / Rocket) are run later with existing scripts. Nothing in baselines/ or evaluation/ is modified.

Dimensions

Signal generator Event generator
AR (reuse generate_signals_Ap) predefined (criteria on windows)
ARIMA (new: AR(p)+MA(q)+differencing d) ML model (SVM inference with a pre-trained model; training is external)

4 datasets total (2 × 2). The recognition-model column is downstream, not part of generation.

How to run

One combination per invocation — no loop. Configure in pipeline_config.json, then run once per combo:

python run_pipeline.py # uses combo set in config
python run_pipeline.py --signal-gen ARIMA --event-gen ml # override the combo
python run_pipeline.py --config my_config.json # alternate config

Edit the config (or pass flags) between runs to produce each dataset yourself.

Files created

  • signal_generators.py — generate_signals_AR (wraps existing AR(p)); generate_signals_ARIMA (new: ARMA loop + d integrations, then de-trend/rescale).
  • event_generators.py — generate_events_predefined (reuse tools); generate_events_ml (inference-only using a pre-trained SVM via svm_utils).
  • run_pipeline.py — single-combo CLI entrypoint; prints basic_event_stats, writes CSVs.
  • pipeline_config.json — active combo + all params + output dir.

Reused (imported, not modified)

  • GenData/generator/signal_generation_tools.py — generate_signals_Ap, generate_events, events_point_to_interval, filter_close_intervals, basic_event_stats, ar_from_timescale.
  • baselines/svm-baseline/svm_utils.py — build_dataset, create_model, run_inference (added to sys.path; folder name has a hyphen).
  • baselines/svm-baseline/config.json — read-only SVM feature config.

Config keys (pipeline_config.json)

  • combo signal_gen: "AR" | "ARIMA"   event_gen: "predefined" | "ml"
  • signals N, f0, T, seed, mu_std[], ar_timescales[[tau,p]], and for ARIMA ma_params[[...]] + d
  • predefined window_s, min_gap_s, and event_defs_path (a shared path string, or a per-signal-generator map, e.g. {AR, ARIMA}, since ARIMA needs thresholds calibrated to its local statistics)
  • ml mode=inference_only, model_path, confidence_threshold, svm_config_path
  • leakage guard model_meta.trained_on_dataset_id must differ from inference_meta.inference_dataset_id when checks are enabled.
  • output output_dir

Output

GenData/pipeline/output/<signal_gen>_<event_gen>/sigs.csv & events.csv

  • sigs.csv: time_s, sig_1 … sig_N
  • events.csv: time_start, time_end, eID

Key decisions

  • ML events = inference-only in this pipeline. The SVM must be trained manually outside GenData/pipeline/, then loaded via ml.model_path.
  • This enforces separation between generation and evaluation/training and avoids train/test leakage inside one pipeline run.
  • ARIMA = manual extension of the AR(p) code (no new dependency).
  • CSV-only output; SVM utils operate on in-memory DataFrames, so the XLSX/CSV CLI mismatch is irrelevant.
